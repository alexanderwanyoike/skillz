# Platforms and media

Read the relevant sections for the current update. These are editorial defaults, not fixed platform limits. Verify current upload specifications, API support and account restrictions with connected tool capabilities or official platform documentation when needed for the chosen deliverables. Do not guess duration, file-size, aspect-ratio or character limits.

## Adapt the story

| Destination | Useful starting point | Prepare when relevant |
| --- | --- | --- |
| X | One concrete change with a screenshot or short clip. Use a thread only if the story needs it. | Exact post or numbered thread, attachments, alt text and project link. |
| LinkedIn | What changed, the problem it addresses and a useful implementation lesson. | Readable paragraphs, demonstration and a natural project link. Avoid generic professional inspiration. |
| Facebook | An accessible project update for the selected audience. | Copy, selected image or video, link and confirmed profile or Page. |
| Instagram | A visual demonstration, carousel or Reel. | Media order, caption, cover, alt text and subtitles. Do not rely on a caption URL as the only way to reach the project. |
| TikTok | Show the result early, then the change or process. | Vertical video, caption, cover and readable subtitles. Do not add trends or music merely for engagement. |
| YouTube Shorts | A self-contained short demonstration with enough context to understand it. | Finished video, title, description, cover options where supported and subtitles. |
| YouTube | A fuller first look, walkthrough or narrated progress report when the update warrants it. | Finished video, title, description, thumbnail, subtitles and chapters if useful. |

The same clean video can serve several destinations with different text and covers. Inspect crops and overlays for each export. Do not reuse a file bearing another platform's watermark.

For an update too small for a longer YouTube video, propose a specific omission or alternative and let the user decide. A shared Short is still a Shorts deliverable; do not imply it also fulfills a requested long-form video.

## Capture genuine product behavior

- Reuse the manually verified user journey from the coding work. Run the relevant application and capture the real rendered result. Keep labels such as prototype, local build and released version accurate.
- Select the useful screen area, make the cursor and text legible and remove irrelevant dead time. Check the actual capture for credentials, private notifications, customer data and unrelated windows before sharing it.
- Use browser or application capture tools that actually exist. A screenshot API does not imply screen recording capability. If recording is unavailable, prepare the route and short shot list, then ask for only the missing capture while continuing the rest.
- Keep original captures and derive crops or edits. Do not alter a product screenshot to imply behavior that was not implemented.

## Choose the media tool

### Prezi

Here, Prezi means the user's in-development application for Remotion slideshows and videos, not an assumed connection to the public presentation service. Locate its available connector or the explicitly identified project and follow its own instructions. Use it for a sequence of screenshots, explanatory slides, project visuals and narration. Check current rendering and export support before relying on it.

### Forgecut

Use Forgecut when the update needs edited footage, sequencing, audio, titles or a more substantial video. Follow its live tool contracts:

- List sessions and attach to the explicitly selected instance. Confirm the project identity and revision. Resolve an ambiguous target with the user rather than editing an unrelated open project.
- Read supported capabilities before constructing edits. Use stable item IDs, integer microseconds, labelled batches, expected revisions and unique request IDs.
- On a conflict, reread and reconsider the edit. For an uncertain operation, use its documented recovery semantics and preserve the same request ID and input where required.
- Export the identified revision and sequence, poll the job and inspect the completed artifact. An editing job or preview render is not a social publication.

### Clipforge

Discover and inspect the actual application's capabilities before choosing it. Use it for clipping or repurposing only if supported. Do not invent command names, project paths, APIs or export options from the product name.

### Generated artwork

Use the available image generation tool and applicable imagegen skill for artwork, backgrounds or thumbnail concepts. Keep the composition restrained and connected to the update. Illustrations can support the story; product demonstrations should remain authentic. Show the actual generated result in the review package.

## Narration

Prepare a short, natural script matched to the edit, with a clear start and end. Ask the user to record only after the script is ready. Incorporate their recording, balance it against other audio and check that the result remains intelligible on a phone. Use licensed music or sound only when needed; do not assume that a platform's music library permits reuse on other platforms.

## Inspect before review

- Inspect final images at the intended viewing size. Check cropping, text legibility, factual labels, covers and attachment order.
- Play final video with audio and check the beginning, ending, pacing, narration sync, captions and any important screen text. Use the available media inspection or playback tools; if full playback or listening is unavailable, state precisely what was checked and ask the user to check the remaining part in the preview.
- Confirm that the actual file presented for approval is the export to be uploaded. Re-exporting with a changed edit creates a new asset revision that needs review.
- Present the real image or playable media through the host's supported preview mechanism. If inline playback is unavailable, provide an accessible file preview or download and explain that the finished video still needs to be watched before approval. Never treat a poster frame as a playable preview.
